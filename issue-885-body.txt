∩╗┐Γê⌐ΓòùΓöÉ## Summary

Two related bugs in the agent chat HTML rendering pipeline share a root cause in the insertion model and must be fixed together as a comprehensive refactoring of ID assignment and DOM insertion:

1. **Live output stops appearing mid-session** Γò¼├┤Γö£├ºΓö£Γòó the pipeline loses track of DOM insertion points after tool-call group promotion replaces element IDs, causing subsequent `document.getElementById` calls to return `null` and DOM commands to be silently dropped.
2. **History loads in wrong order with auto-scroll suppressed** Γò¼├┤Γö£├ºΓö£Γòó when opening an agent chat, history is loaded oldest-first, so the user sees nothing useful until all history has loaded, then the page jumps to the bottom. The desired behaviour is newest content visible immediately with older history back-filling above.

Both bugs stem from the same architectural weakness: element IDs are assigned by a monotonic counter (encoding *insertion order*, not *logical position*), and insertion points are tracked by scanning adjacent siblings rather than stable anchor elements. The fix replaces the entire ID and insertion model.

---

## Root Cause

### Bug 1 Γò¼├┤Γö£├ºΓö£Γòó Insertion-point loss from tool-call group promotion

**File:** `Phantom.Workspaces.Agent.Gui\ViewModels\DocumentModels\ChatOutputHtmlModels.cs` lines 735Γò¼├┤Γö£├ºΓö£Γöñ753

The current insertion-point resolver scans adjacent siblings via `IsInserted` flags:

```csharp
public static (ChatOutputUpdateLocation Location, string Reference) ResolveInsertTarget<T>(
    IList<T> target, int index, string containerPath,
    Func<T, bool> isInserted, Func<T, string> elementId)
{
    if (index - 1 >= 0 && isInserted(target[index - 1]))
        return (ChatOutputUpdateLocation.After, elementId(target[index - 1]));

    if (index + 1 < target.Count && isInserted(target[index + 1]))
        return (ChatOutputUpdateLocation.Before, elementId(target[index + 1]));

    return (ChatOutputUpdateLocation.Append, containerPath);
}
```

This breaks when tool-call group promotion fires. **File:** `ChatOutputHtmlModels.cs` lines ~510Γò¼├┤Γö£├ºΓö£Γöñ576 (`ChatMessageHtmlTransformer.OnInsert`): when the second consecutive tool-call-only message arrives the previous standalone `msg-N` element is **replaced** wholesale:

```csharp
this.sink.UpdateContent(
    prevSlot.Model.ElementId,          // e.g. "msg-5"
    ChatOutputUpdateLocation.Replace,
    group.BuildHtml(prevSlot.Model.BuildHtml()));
// msg-5 is gone from the DOM; grp-12 takes its place
```

`msg-5` no longer exists. Any `ResolveInsertTarget` call that resolves to `After msg-5` results in `document.getElementById("msg-5")` returning `null`, the JS posts `commandFailed`, and since `NotifyInsertionFailed` only recovers running items (not history items), the command is silently dropped. All subsequent insertions near that slot fail the same way.

### Bug 2 Γò¼├┤Γö£├ºΓö£Γòó Wrong history load iteration order

**File:** `ChatOutputHtmlModels.cs`, line 1036

`ComputeChunkRanges` (line 1222) returns chunks **newest-first**: `chunks[0]` = most recent slice, `chunks[Count-1]` = oldest. The load loop iterates **`Count-1` down to `0`**, so the oldest chunk is rendered first and the newest last:

```csharp
// Line 1036 Γò¼├┤Γö£├ºΓö£Γòó iterates oldest-first:
for (var chunkIndex = chunks.Count - 1; chunkIndex >= 0; chunkIndex--)
```

`isLastChunk` (line 1047) is defined as `chunkIndex == 0` Γò¼├┤Γö£├ºΓö£Γòó the newest chunk Γò¼├┤Γö£├ºΓö£Γòó but because of the inverted loop, this is only reached on the last iteration.

### Bug 3 Γò¼├┤Γö£├ºΓö£Γòó No prepend operation

**File:** `chat-output-shell.html` lines 658Γò¼├┤Γö£├ºΓö£Γöñ660; `IChatOutputHtmlSink.cs`

The JS `applyCommand` handles `replace`, `before`, `after`, `append` but **no `prepend`/`afterbegin`**. All history chunks are appended bottom-to-bottom, so even reversing the loop order alone would render chunks newest-at-top rather than newest-at-bottom.

### Bug 4 Γò¼├┤Γö£├ºΓö£Γòó Auto-scroll suppressed for entire load

**File:** `AgentChatOutputControl.axaml.cs` lines 120Γò¼├┤Γö£├ºΓö£Γöñ123, 264

`suppressSinkScroll = true` is set before loading begins. `ScrollToBottom()` silently clears the flag on first call but does not scroll:

```csharp
// Lines 120Γò¼├┤Γö£├ºΓö£Γöñ123:
if (this.suppressSinkScroll)
{
    this.suppressSinkScroll = false;   // clears flag, does NOT scroll
}
```

Because the loop is inverted (Bug 2), `ScrollToBottom()` is only called after all chunks have been appended. The combined effect: the user sees nothing useful until the entire history load completes, then the page jumps to the bottom.

### Why notifications keep working

`AgentChatStatusLineViewModel` uses pure Avalonia property bindings Γò¼├┤Γö£├ºΓö£Γòó no WebView, no DOM commands. It is completely independent of the `IChatOutputHtmlSink` pipeline and is unaffected by insertion-point loss.

### Secondary contributing factor (#884)

Due to **#884** (`IsVisible` binding resolves against `AgentViewModel` instead of `SubAgentSlotViewModel`), every spawned sub-agent creates a permanently-active `AgentChatEditorControl` with its own live `ChatMessageHtmlTransformer`. Each model fires `CollectionChanged` callbacks at `DispatcherPriority.Normal`, starving the root agent's background-priority auto-flush timer. This exacerbates how quickly the output appears frozen but is a separate bug fixed by #884.

## Design / Fix

Replace the fragile sibling-scanning insertion model with **positional IDs** and **explicit `insert-after` anchor divs**, and simultaneously fix history load order and auto-scroll.

### 1. New shell structure

Replace the three container divs with four semantic anchor divs:

```html
<body>
  <div id="load-after"></div>           <!-- anchor: newest history chunk inserted after this -->
  <div id="history-before"></div>       <!-- anchor: history updates inserted before this -->
  <div id="running-items-inside"></div> <!-- container: running (streaming) turns -->
  <div id="subagent-items-inside"></div><!-- container: sub-agent status panel -->
  <script>Γò¼├┤Γö£├ºΓö¼┬¼</script>
</body>
```

`load-after` is an empty sentinel. During history load the newest chunk is inserted after it (`afterend`); each older chunk is prepended before the previous chunk's first element (`beforebegin`). After load, `load-after` remains as a stable anchor.

### 2. New ID scheme Γò¼├┤Γö£├ºΓö£Γòó positional, not counter-based

Replace `msg-{N}` (monotonic counter) with `history-{idx}-{subidx}` where `idx` = index in `AgentChatHistory` and `subidx` = index of the content block within the item.

| Element | Old ID | New ID |
|---|---|---|
| History message wrapper | `msg-3` | `history-3` |
| History message header | `msg-3-header` | `history-3-header` |
| History message contents container | `msg-3-contents` | `history-3-contents` |
| History content block | `msg-3-c0` | `history-3-0` |
| Insert-after anchor (item-level) | _(none)_ | `insert-after-3` |
| Insert-after anchor (content-level) | _(none)_ | `insert-after-3-0` |
| Tool grouping | `grp-12` | `tool-grouping-3-0` (idx/subidx of first tool_use) |
| Tool grouping summary | `grp-12-summary` | `tool-grouping-3-0-summary` |
| Tool grouping body | `grp-12-body` | `tool-grouping-3-0-body` |
| Insert-after for tool grouping | _(none)_ | `insert-after-{highest-idx}-{highest-subidx}` |
| Running item container | `run-7` | `run-7` _(unchanged)_ |
| Running item contents | `run-7-contents` | `run-7-contents` _(unchanged)_ |

### 3. Explicit `insert-after` anchor divs

Every inserted item is followed immediately by an empty `<div class="insert-after">` with a stable ID:

```html
<!-- history item 3 -->
<div class="chat-message" id="history-3">
  <div class="chat-header" id="history-3-header">Γò¼├┤Γö£├ºΓö¼┬¼</div>
  <div class="chat-contents" id="history-3-contents">
    <div class="chat-content chat-text" id="history-3-0">Γò¼├┤Γö£├ºΓö¼┬¼</div>
    <div class="insert-after" id="insert-after-3-0"></div>
  </div>
</div>
<div class="insert-after" id="insert-after-3"></div>

<!-- tool grouping starting at item 5, content 0 -->
<details class="chat-tool-group" id="tool-grouping-5-0">
  <summary id="tool-grouping-5-0-summary">Γò¼├┤Γö£├ºΓö¼┬¼</summary>
  <div class="chat-tool-group-body" id="tool-grouping-5-0-body">
    <div class="chat-message" id="history-5">Γò¼├┤Γö£├ºΓö¼┬¼</div>
    <div class="insert-after" id="insert-after-5"></div>
    <div class="chat-message" id="history-6">Γò¼├┤Γö£├ºΓö¼┬¼</div>
    <div class="insert-after" id="insert-after-6"></div>
  </div>
</details>
<div class="insert-after" id="insert-after-6-0"></div>
```

Insertions always use `afterend` on the appropriate `insert-after-*` div. Because `insert-after` divs are independent elements (not part of the item being promoted/replaced), **they survive tool-group promotion unchanged**. `ResolveInsertTarget` and `IsInserted` flag scanning are deleted entirely.

### 4. Add `Prepend` to enum and JS

In `IChatOutputHtmlSink.cs`:
```csharp
Prepend,   // insertAdjacentHTML("afterbegin") Γò¼├┤Γö£├ºΓö£Γòó insert as first child
```

In `chat-output-shell.html`, add to `applyCommand`:
```javascript
case "prepend":
    target.insertAdjacentHTML("afterbegin", command.content);
    break;
```

In `AgentChatOutputControl.axaml.cs`, update `ToWireLocation` to map `Prepend Γò¼├┤Γö£├æΓö£├Ñ "prepend"`.

### 5. History load order ╬ô├ç├╢ all chunks insert After `load-after`

Because `load-after` is a stable sentinel, every chunk uses `After load-after` (`insertAdjacentHTML("afterend", ╬ô├ç┬¬)`). Each older chunk naturally squeezes in between `load-after` and the previously-inserted chunk:

`
Initial:           [load-after]
After chunk 0:     [load-after][chunk-0 ╬ô├ç├╢ newest]
After chunk 1:     [load-after][chunk-1][chunk-0 ╬ô├ç├╢ newest]
After chunk 2:     [load-after][chunk-2][chunk-1][chunk-0 ╬ô├ç├╢ newest]
`

No `isFirst` tracking needed. No `Prepend` operation needed for the load path:

```csharp
// Iterate chunks[0] (newest) first ╬ô├ç├╢ all target load-after
for (var chunkIndex = 0; chunkIndex < chunks.Count; chunkIndex++)
{
    // ╬ô├ç┬¬ render chunk off-thread, replay commands into DOM ╬ô├ç┬¬
    this.sink.UpdateContent("load-after", ChatOutputUpdateLocation.After, chunkHtml);

    if (chunkIndex == 0)
        this.sink.ScrollToBottom(); // scroll immediately ╬ô├ç├╢ newest content now visible
}
```

Auto-scroll is **enabled from the start** of history load (not suppressed). It keeps the bottom (newest content) visible while older chunks fill in above.
### 6. Remove `suppressSinkScroll` suppression during load

Remove or reorder the `suppressSinkScroll = true` assignment so it does not suppress the `ScrollToBottom()` call after the newest (first-iterated) chunk. With the corrected loop, `ScrollToBottom()` fires after the very first iteration and the user immediately sees the most recent content.

### 7. Remove `NotifyInsertionFailed` silent-drop for history elements

With explicit `insert-after` divs, history insertion failures should not occur in normal operation. Change the `commandFailed` handler to log an error for history elements rather than silently returning, to catch regressions.
